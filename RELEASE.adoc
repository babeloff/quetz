== Create a release

A release is a GitHub release containing the tracked source archive,
SHA-256 checksums,
and one native conda package for every supported workspace platform:
`linux-64`,
`osx-64`,
and `osx-arm64`.
Windows is not a supported workspace platform.
Releasing does not publish a container or mirror packages to a channel.

Update the version with `pixi run -e dev tbump --no-tag --no-push NEW_VERSION`.
Refresh `pixi.lock` with `pixi lock`.
Update the changelog and run the checks:

[source,bash]
----
pixi run --locked -e dev test
pixi run --locked -e lint lint
pixi run --locked -e docs docs
pixi run --locked -e release check-python
----

Commit and push the changes,
then create and push the matching `vNEW_VERSION` tag.
The `Release source and conda packages` workflow builds on native Linux,
Intel macOS,
and Apple Silicon runners.
It validates the version tag and package metadata before attaching artifacts to the GitHub release.
The workflow can also be dispatched for an existing tag when no release has been created yet.
An existing release is never overwritten automatically.

For local artifact inspection,
run `pixi run --locked -e release build-conda` on the target platform.
This uses `pixi publish --target-dir` to copy the built package into a local directory.
It does not upload to a registry.
The platform build string prefixes keep artifact names unique across platforms.

The assembly command requires the full platform set by default.
For local Linux verification,
use `pixi run --locked -e release prepare-release --platform linux-64` after committing the version update.
The source archive comes from the current Git commit and includes plugins and documentation.
The assembler checks package identity,
version,
and platform coverage and generates `SHA256SUMS`:

== Publish an existing release

Run the separate `Publish release to GHCR and prefix.dev` workflow manually with the release tag.
It verifies the released checksums,
mirrors those exact conda packages to https://prefix.dev/mesoforge[mesoforge],
and uses Podman to build and push `ghcr.io/babeloff/quetz:vNEW_VERSION`.
Neither a push to `main` nor a release tag invokes publication.

GitHub Actions supplies the GHCR token with package-write permission.
Set the repository secret `PREFIX_DEV_TOKEN` to a prefix.dev token authorized to upload to `mesoforge`.
Publication uses Pixi's prefix uploader and Podman's registry login,
build,
and push commands.
If publication fails after one registry succeeds,
inspect that registry before retrying;
the two registry operations are independent.
